## Diagnosis and implementation

The production capability endpoint returned `{"google":true,"apple":false}`. `vercel env ls production` confirmed no `APPLE_BUNDLE_ID`, `APPLE_SERVICE_ID` or `APPLE_CLIENT_SECRET`. The actual signed build-6 archive has `com.apple.developer.applesignin=[Default]`, production APNs and `get-task-allow=false`; the app entitlement is present. The server unnecessarily required browser credentials before accepting native Apple ID tokens.

`packages/auth/src/apple.ts` now supports native Apple using only the registered bundle audience, with browser OAuth enabled only when its Service ID and client secret are complete. The public endpoint adds `appleNative` while preserving browser `apple`. Mobile checks both device support and the appropriate server flag, with compatibility for older server responses. The installed Better Auth 1.7.6 verifier still enforces Apple JWKS, issuer, expiry, allowed audience and raw/SHA-256 nonce. No custom verification override or unverified success was introduced. Native first-use names are passed separately to Better Auth.

The mobile form keeps the 56px brand, existing fonts/palette, Apple system button, Google and email. It removes welcome taglines, doodles, overlapping panels and animated hidden code cells. Copy is Sign in / Send code, with corresponding plain Spanish. The code field is visible and retains OS autofill. Resend, expiry, change-email, language persistence and public help links remain. Submissions are mutually exclusive and show progress on the selected action. Cancellation is quiet. Shared disabled buttons retain readable text and loading retains contrast. The logo behaves as a fixed brand asset; the sign-in display heading caps scaling at 1.5 while form text continues to scale.

Completing a task still saves through the atomic local/outbox mutation, reminder reconciliation and synchronization. It no longer creates an Undo notice. Completed history still offers Reopen; other Undo behavior is preserved.
