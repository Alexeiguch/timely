# 004 — Native planner interaction and scoped Undo

Continue the existing Expo SDK 55 / React Native 0.83 app with authenticated Expo Router tabs (Planner, Review, Search, Settings). The account provider selects a SecureStore identity for offline access; it never supplies server authorization. The planner provider owns the account/environment-specific SQLite store, shared sync engine, foreground/network/zone refresh, editor and transient Undo. Tasks stay behind authenticated, owner-checked APIs.

Use `@react-native-community/datetimepicker` 8.6.0, the exact version in Expo's installed compatibility manifest, for civil date and time inputs. Picker adapters read local calendar fields, never UTC ISO slices. Bundle the genuine Nunito Sans bold face along with the existing regular body and Baloo heading fonts. Generate iOS/Android projects with Expo prebuild; generated native folders are ignored. No signing credentials or release publishing are involved.

Day/Week/Month use shared domain projections and sorting. SectionList/FlatList virtualize task rows; recurring month groups use a deliberately horizontal occurrence strip. Week uses a day strip with an explicit whole-week view. The small month calendar can scroll horizontally at the narrowest widths to preserve 44-point day targets. Period swipes are confined to the period heading via React Native's built-in PanResponder so task scrolling and horizontal occurrence strips keep their own gestures. Explicit period/move/reorder controls are always available. This is a narrow initial alternative to the planned Gesture Handler/Reanimated drag implementation, which remains a follow-up rather than a claimed feature.

The full native editor calls shared task validation, presets, recurrence preview and summaries. The scope chooser is presented after editing and before saving. It excludes occurrence-only scope for structural recurrence changes. Only changed field groups enter an edit command, preserving independent concurrent edits. System reminder scheduling remains stage 07; task reminder policy can be saved but the UI explicitly says delivery is not yet available.

Undo emits a new operation. State Undo restores the previous state and its matching immutable terminal snapshot; move Undo restores the previous schedule. Scoped delete Undo is a `restore` referencing `deletionId`, matched against the original target/scope and a later stamp. Replay retains both journal entries and omits only that specific deletion, preserving other deletions and edits. A future-range restore without a deletion ID is invalid. This extends the unreleased v1 protocol; backend and clients must be updated together before testing these operations. Older deployed clients that do not understand this field are not compatible. No database schema change is required.

Manual untimed ordering uses a batch of order commands in one local transaction, with matching outbox writes. Sync still sends bounded batches; invalid local batches roll back entirely. Reordering changes neither civil date nor recurrence. Long-press drag is not implemented in this milestone.

Deep links use `/?day=YYYY-MM-DD&occurrenceId=UUID&ownerId=ACCOUNT`. Only the authenticated/cached account's already-selected namespace is searched. The URL owner is checked, never accepted as authority. Moved occurrences resolve via saved exceptions; invalid dates, foreign owners, deleted ranges and unavailable items are rejected without writes. Links carry no titles/notes or session data. Notification listeners/actions are deferred to stage 07.

Review and Search currently query a selected local range of at most 366 days. Settings reports current zone, sync/download status, pending count and session-only grouping. Synchronized preferences, account deletion, native reminder delivery and indexed local migration/recovery remain their respective earlier/later-stage work; no placeholder success is shown.
