# 012 — Recurring task streaks

The owner requested streaks and confirmed that they use the task's existing deadline and that streak tasks cannot be skipped. This extends the original product scope; [STREAKS.md](../planner/STREAKS.md) is the canonical behavior contract.

Persist a nullable, optional tracking-start policy in task creation/series-edit commands. Keep legacy absence unchanged so existing journal fingerprints remain stable. Tracking is a series choice, not an occurrence-only override. Existing atomic offline writes, canonical journal replay, authenticated owner-scoped APIs and JSON persistence carry it without a SQL migration. Validate that enabled tracking requires recurrence. Reject Skip in both the shared state use case and new sync command admission; admission checks the effective active revision independently of the incoming clock so stale or backdated clients cannot bypass tracking through an old target. Canonical replay never revalidates accepted Skip commands against later policy changes. Terminal state commands retain the streak policy of their immutable authored revision, including legacy absence, so a delayed earlier edit cannot rewrite plain terminal history or stall synchronization.

Derive counts rather than incrementing a stored total. Both platforms use the same bounded series projection, immutable source ordering and terminal snapshot deadline comparison. Successful runs continue across projection windows; the seven displayed marks are not a history retention limit. Pending future deadlines do not break a run. Ordinary future-slot completions wait for their day to enter the current count; moved future slots use their effective scheduled day and deadline. A late completion cannot repair a missed deadline, even though ordinary task progress still counts it as completed.

Use the existing flame/check/cross vector icons and approved orange/lime/neutral surfaces. Display the same indicator on individual task cards and grouped month cards. Enabling an existing series starts from today; historical terminal policy and schedule remain unchanged. Local release preparation includes type checks, business/sync/DB checks, real authenticated desktop/phone browser tests and iOS/Android Hermes exports. New native on-device streak interaction proof is still pending.
