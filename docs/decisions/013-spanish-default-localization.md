# 013 — Spanish default and English language choice

The owner requested English and Spanish throughout the web and mobile apps, with Spanish as the default. Start in Spanish regardless of the operating system or browser language. Offer Español / English on sign-in and in Settings; switching updates the current screen without signing out or changing plans.

Keep the choice on each device: browser localStorage and native SecureStore under `timely-language`. Browser tabs share changes through storage events. The choice works offline and survives restart. Missing, unsupported or corrupt values resolve to Spanish. Preserve a choice made during asynchronous storage restoration, serialize writes, and show a localized message if persistence fails. This is a device presentation preference, so it does not alter the account preference protocol or require a SQL migration.

`@timely/i18n` owns the English source keys, Spanish catalogue, interpolation, locale selection and presentation of validated recurrence/streak projections. Each app owns its React subscription/provider so web and native use their respective installed React versions. Recurrence generation, task state, occurrence identity, deadline rules and synchronization stay in the shared domain. Translate interface text, accessible labels, dates, filters, errors and reminders; preserve authored titles, notes, addresses and identifiers verbatim. Unknown technical errors use a safe localized fallback.

Sign-in clients send the selected language through `x-timely-language` when requesting an email code. The server validates that presentation hint independently for every request and defaults to Spanish; it grants no authority and changes no authentication checks. Resend and capture-mode mail use the same localized subject, text and HTML. Native scheduled reminder data records its language; reconciliation replaces this environment's old-language reminders when the choice changes. OS permission sheets and provider consent pages remain controlled by their respective providers.

Acceptance includes catalogue placeholder parity, UI message coverage, delayed storage restoration/failure, recurrence without mutation, bilingual mail, real browser authentication and offline authored-content preservation. Desktop and 320px phone browser cases pass. Both native Hermes exports pass; the running iOS simulator renders both languages and restores Spanish after a process restart. This is not evidence of Android runtime, physical-phone interaction, human inbox delivery, provider consent or actual notification delivery; those existing release gates remain open.
