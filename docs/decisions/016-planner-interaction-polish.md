# 016 — Editor, calendar and sign-in interaction fixes

The owner reported an occluded native save action, unfriendly minute entry, a quiet streak option, the Weekdays choice highlighting Weekly, faint month task markers, missing calendar swipes and isolated/untranslated native sign-in UI.

Keep the supported Expo 57 / React Native 0.86 dependency set. Draw the rounded native sheet inside a transparent full-screen modal, with its own safe-area provider. This keeps view and keyboard coordinates in one coordinate space. The original iOS `pageSheet` reported its content at y=0 despite appearing 62 points below the screen origin on the test phone; measuring that view alone still left Save behind the keyboard. The new container supplies the screen safe-area top inset to `KeyboardAvoidingView` before autofocus, gives the form an explicitly flexible scroll region and moves the fixed footer with keyboard avoidance. Disable ScrollView's automatic keyboard insets to prevent applying keyboard space twice. This follows the installed implementation and [React Native keyboard avoidance documentation](https://reactnative.dev/docs/0.86/keyboardavoidingview); actual keyboard-open acceptance is recorded in progress.

Replace duration's raw numeric input on both clients with optional quick choices (15/30/45 minutes, one/two hours) and custom day/hour/minute controls. Preserve exact existing minute values and the 1–10,080-minute contract, including multi-day estimates; clearing duration remains independent of start time. Duration is effort, not a wall-clock date/time picker. Shared localized formatting is in `@timely/i18n`.

Derive the displayed recurrence preset in the shared domain: a one-week rule containing exactly Monday–Friday is Weekdays. Other weekly selections/intervals remain Weekly. This changes presentation only; persisted grammar, cadence, recurrence ends and historical identities are unchanged. Both editors use the same helper.

Put streak opt-in directly after recurrence choice, before advanced customization. Use original vector flame artwork, a warm orange panel, a pumping flame/glow and rising spark. Native animation uses the installed Animated API with a native driver and no interaction handle; stop it while off, backgrounded or unmounted, and react to reduced-motion preference changes. Web CSS honors `prefers-reduced-motion`. Keep the existing deadline, opt-in and no-Skip behavior.

Fit the native month grid to available width and replace faint dots with task counts and highlighted dates. Use explicit rows of seven flex cells: percentage widths caused Yoga rounding to wrap the seventh column on the actual iOS fixture. Count the projected effective dates so recurrence and moved occurrences remain correct. Attach an intentional horizontal swipe to the calendar itself; leave vertical agenda scrolling and horizontal occurrence strips independent. Preserve the explicit Previous/Next alternatives. Web shares its existing heading swipe behavior with the grid and suppresses the synthesized date click after a swipe.

Connect native sign-in's brand, welcome heading and existing calendar doodle in a soft blue panel above the white entry card. Keep Google-first provider ordering, conditional divider, one code recipient, autofill and language persistence. Translate all local action-helper arguments, including Send me a code, Sign in and Change email, plus the empty start-time choice. Extend the localization guard to catch untranslated native sign-in helper labels.

No schema, authentication, provider, deployment or native dependency changes are needed. See [progress](../progress.md) for actual checks, artifacts and outstanding physical/Android evidence.
