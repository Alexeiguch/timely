# Gentle daily summaries

The owner requested reminders to finish tasks without frequent nagging and selected one daily summary. Add a quiet, opt-in mobile setting with an initial 18:00 local time. Keep explicit task alarms optional. The daily summary covers eligible unfinished work for that date, without an old overdue backlog or missed-summary catch-up.

`DailySummary` in the shared domain computes one finite plan for each qualifying date within the seven-day horizon. It uses real recurrence/exception/terminal projections and device-zone civil dates. Untimed plans count; timed plans starting later than the chosen summary do not. It emits a count, date and stable daily identity, not authored titles or notes. Native and server candidates use this same planner. Native replaces a pending summary when its count changes, cancels it after the last qualifying plan is finished, and reserves its OS-budget slot ahead of optional task alarms.

Store the setting with installation notification metadata, and register it behind the authenticated device/owner API. Migration 0006 adds disabled-by-default `summary_enabled` and `summary_time` to `notification_devices`. Older clients omit the setting and keep their previous behavior. No new operation is added to the account sync feed, so existing strict protocol-v1 task clients can continue syncing. Web Settings points to the mobile configuration.

Track elapsed local summary dates durably and return consumed dates during remote preparation. Server claims, under the owner lock, reject another committed or elapsed-local summary for the same installation/date even when its schedule version changed. Content changes share one identity; timing/zone changes invalidate schedules without admitting another same-day notification after handling. Keep the last acknowledged remote policy locally so offline time edits can preserve known local ownership without acquiring a competing remotely owned summary. The existing provider response-loss, retry, token invalidation and receipt semantics remain in force.

Native summaries omit sounds, use a low-importance non-vibrating Android channel and suppress foreground banners; remote payloads use no sound and normal delivery priority on that channel. An already-planned remote job expires after five minutes. OS delivery remains best effort. Taps validate account/backend routing and open current-day plans, including after the original plans have been completed. Multiple explicitly enabled devices have independent summaries.

## Hosted cadence — 2026-10-13

Keep the minute Inngest cron (`* * * * *`) and call the worker directly without wrapping the complete sweep in an additional durable step. Each job's claims, provider uncertainty and receipts already live in PostgreSQL; whole-function retries still respect those transitions. One run per minute uses about 43,200 executions in a 30-day month (44,640 in a 31-day month), before retries, within the current free 50,000 allowance. Wrapping the sweep in one Inngest step would double that usage.

A three-minute schedule was considered and initially prepared, but optional before-task alerts expire one minute after their intended time. Retain their timing and cancellation semantics rather than widening their window. Synthetic remote tests retain five minutes of eligibility to survive scheduler jitter. The summary remains once per installation/date with its existing five-minute expiration. The signing key authenticates hosted invocations; an event key is not required by this cron-only workflow. Re-sync the app after deploying the function definition.
